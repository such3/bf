## 5. Guided lesson: stdout vs stderr (your to-do)

You wrote "we need to study something about stderr and stdout". Here is a path to discover it yourself.

**Background to look up:** every process starts with three open streams: standard input (descriptor 0), standard output (1) and standard error (2). `cout` writes to 1; `cerr` writes to 2.

**Experiments** (use any valid BF file, then a bad one):

```bash
./bf prog.bf > out.txt        # what appears on screen? what is in out.txt?
./bf prog.bf 2> err.txt       # now?
./bf prog.bf > out.txt 2> err.txt
./bf prog.bf 2>&1 | head -5   # what does this combination do?
```

Then change **one** error message from `cout` to `cerr` and repeat the first two commands.

**Questions to answer:**

1. For each thing your program prints, decide: is it a *result*, or a *diagnostic* about the program? (banner, argument dump, iteration trace, `.` output, bracket errors, overflow message)
2. Which of them would a user want in `out.txt` if they redirect the output of a BF program? Which would they *not*?
3. Your test script (T-3) will compare output with expected files. What would break if the trace or errors were mixed into that output?
4. `cerr` is unbuffered and `cout` is buffered. Why might that matter when a program crashes right after printing something?

**Connection to your plan:** answering question 1 tells you what the verbose flag (T-2) should control.
